# EGM-Lite Checklist: kali-zsh-setup.sh (rev 12 — standalone self-contained template; rev 11 + Goldfish spec-review round-11 fixes)

Goal: Rewrite [`kali-zsh-setup.sh`](../kali-zsh-setup.sh) as a **single self-contained script** that runs locally on any Debian machine: Kali templates embedded verbatim, no SSH, no Kali host, no second machine. Copy the one file anywhere on the target, run it, get a Kali-identical zsh (system-wide: `/etc/skel` + all interactive profiles, per the earlier "на всех профилях" requirement, which the user did not revoke).

## Deferred empirical tests / blind-spot risks

- `[⏳ ACK-1]` command-not-found database on Debian 13: `/etc/zsh_command_not_found` needs a populated cache; if the package ships without it, the hook may error. Empirical check in smoke stage; never fatal.
- `[⏳ ACK-2]` Harvest classifier coverage on varied bash syntax: validated via the synthetic fixture test, not on live dotfiles.
- `[⏳ ACK-3]` Root dotfiles origin: `root`'s `.bashrc` may come from `/usr/share/base-files/dot.bashrc` rather than `/etc/skel/.bashrc`; preflight compares against both to avoid false-positive harvest.
- `[⏳ ACK-4]` `runuser`/`su` scripted login zsh (`zsh -l -i`, no pty, forced TERM) may differ from a real tty login. Mitigated by explicit env + timeout in the validation gate; residual divergence verified in smoke stage.

## Accepted scoped-down rationales

- System-wide scope (all interactive profiles + `/etc/skel` + default-shell configs) kept from the previously agreed requirement; not reduced to current-user-only.
- Single-file embedding chosen over script + `files/` bundle (see [`egm_lite_alternatives.md`](egm_lite_alternatives.md) Option A); runtime download rejected as non-autonomous.
- `--force-unlock` dropped: `flock` eliminates the stale-lock class it existed for.
- Root user inclusion kept (requirement: replace shell on all profiles).
- Line-based harvest with depth rule kept from previously approved reviews over embedding a heavy full shell parser.
- Users with unusable HOME, broken dotfile symlinks, or non-`/etc/passwd` (LDAP/SSSD) accounts are skipped with WARN/report instead of aborting the whole run (round-1 finding 3/4 policy).
- Validation-gate failures are attributed per-user (skip+WARN, no `chsh`) vs systemic (global abort) instead of abort-always, matching the skip-and-continue policy (round-2 finding 3 policy).
- Mid-pipeline per-user failures (backup, deploy, non-root `chsh`) skip the user with WARN and continue; smoke failures are non-fatal WARNs (round-3 finding 3 policy).
- Symlink write-through restricted to same-owner regular-file targets (round-3 finding 4 policy, narrowed in round 7 to owner-only: `install -o <user>` would silently chown a foreign-owned target, and restore restores bytes but not owner/mode).
