# EGM-Lite Checklist: kali-zsh-setup.sh (rev 7 — standalone self-contained template; rev 6 + Goldfish spec-review round-6 fixes)

Goal: Rewrite [`kali-zsh-setup.sh`](../kali-zsh-setup.sh) as a **single self-contained script** that runs locally on any Debian machine: Kali templates embedded verbatim, no SSH, no Kali host, no second machine. Copy the one file anywhere on the target, run it, get a Kali-identical zsh (system-wide: `/etc/skel` + all interactive profiles, per the earlier "на всех профилях" requirement, which the user did not revoke).

Review baseline: starting commit `3cfc430`; working tree has untracked [`kali-zsh-setup.sh`](../kali-zsh-setup.sh) (rev 16 SSH version, 17 543 bytes) and `egm/`. Before the first edit, record sha256 of the pre-edit script in this checklist as the review baseline (untracked file ⇒ `git diff` alone gives incomplete coverage).

## Tasks

- [ ] Record review baseline: sha256 of pre-edit [`kali-zsh-setup.sh`](../kali-zsh-setup.sh) into this checklist before the first implementation edit.
- [ ] Rewrite script header, `usage()` and CLI: only `--help` and `--preflight`. Delete all SSH-era flags and plumbing (`--source`, `--target`, `--kali-path`, `--force-unlock`, `SSH_OPTS`, `SCP_OPTS`, `remote_exec`, `remote_sudo`). Rationale: `/var/run` lock class disappears with local `flock` (no stale-lock problem, so no unlock flag).
- [ ] Privilege model: if not root and `sudo` exists → re-exec `sudo -- "$0" "$@"`; if not root and no `sudo` → fatal with clear message. Root path runs directly. Rationale: on an arbitrary Debian machine passwordless sudo cannot be assumed; one interactive sudo prompt is acceptable.
- [ ] Local concurrency guard: `exec 9>/run/lock/kali-zsh-setup.lock` + `flock -n 9` (fatal if busy). Keep cleanup traps: ERR/INT/TERM runs already-written per-user and system restore scripts then exits; EXIT removes staging dir and releases the lock fd.
- [ ] Embed templates as quoted heredocs (`<<'KALI_ZSHRC_EOF'`, `<<'KALI_ZPROFILE_EOF'`) inside the script, byte-identical to the pinned upstream files. Add a self-check used by `--preflight` and the install path: extract heredoc body, compare sha256 against the pinned values above; mismatch = fatal template corruption. Rationale: pinned hashes make "verbatim Kali template" verifiable on any machine, offline.
- [ ] Preflight stage (read-only, zero mutation; **exit contract: 0 only when warning-only, non-zero on fatal-class findings — template hash mismatch or unusable environment**): check Debian via `/etc/os-release` (warn if not Debian); `apt-cache policy` candidates for `zsh`, `zsh-syntax-highlighting`, `zsh-autosuggestions`, `command-not-found`; discover interactive users (`getent passwd`, UID 0 + UID ≥ 1000, filter nologin/false/sync). Per-user audit: HOME existence check — a user whose home directory is missing or unusable is **skipped entirely** (no backup, no deploy, no `chsh`) with an explicit WARN, and the run continues for remaining users; symlink audit — `.zshrc`/`.zprofile` symlinks must resolve to an existing regular file owned by the same user or located inside that user's home directory, otherwise the user is skipped with WARN (covers broken targets, directory targets, and foreign/shared targets such as dotfiles repos outside the home); accounts not present in `/etc/passwd` (LDAP/SSSD) are marked and **skipped with a report** (`chsh` does not manage directory accounts); bash-only constructs in `~/.profile` (WARN, framed in the `emulate sh -c` execution context they will run under); `~/.zshenv` audit — existence report plus the same bash-construct WARN scan as `~/.profile` (the validation gate executes each user's `~/.zshenv` on every zsh invocation), plus ZDOTDIR detection: `ZDOTDIR` set in `/etc/zsh/zshenv` ⇒ fatal WARN with cause before any mutation (system-level: deployed dotfiles would be inert machine-wide); `ZDOTDIR` set in the user's `~/.zshenv` ⇒ per-user WARN + skip with explanation that deployed `~/.zshrc`/`~/.zprofile` would not be read; `~/.bash_profile` existence check (WARN: zsh never reads it — bash prefers it over `.profile`, so its portable lines are harvested instead, see harvest task; the WARN also discloses that `.profile` now executes in zsh login sessions where bash had been skipping it — review its contents); migration diff preview (existing `~/.zshrc` vs embedded template; existing `~/.zprofile` vs embedded template — WARN when the existing file is non-trivial: it is replaced without migration; `~/.bashrc` vs `/etc/skel/.bashrc` or `/usr/share/base-files/dot.bashrc` for root); system skel preview — existing `/etc/skel/.zshrc`/`.zprofile` vs embedded template with the same WARN when non-trivial (admin-customized skel is replaced without migration); harvested `source`/`. <file>` lines are WARNed and listed explicitly in the preview (a bash-oriented sourced file may diverge silently under zsh); print heredoc sha256 self-check result.
- [ ] System backup (first mutation, before any snapshotted file changes): timestamped `/etc/zsh-system-backup-<UTC>` (0700 root), immutable baseline dir + `-latest` symlink, snapshot `/etc/zsh/zprofile`, `/etc/zsh/zshenv`, `/etc/zsh/zshrc`, `/etc/shells`, `/etc/skel/.zshrc`, `/etc/skel/.zprofile`, `/etc/default/useradd`, `/etc/adduser.conf` (record absence for not-yet-existing files), generated `restore-system.sh` (restores files only, keeps installed packages; a path recorded as absent is **deleted** by restore — full pre-run state, with the known caveat that an already-installed zsh is left without its conffiles until a later package upgrade recreates them). Snapshot must capture pre-run bytes: nothing in the list may be modified before this stage.
- [ ] Package install: `DEBIAN_FRONTEND=noninteractive apt-get install -y -o DPkg::Lock::Timeout=60 zsh` — fatal if this fails; plugins `zsh-syntax-highlighting zsh-autosuggestions command-not-found` best-effort: attempt, collect failures, print a "missing optional features" report, continue. `apt-get update` when `apt-cache policy` shows a missing candidate, plus a single fetch fallback: on a fetch error (404 / Hash Sum mismatch) run `apt-get update` and retry the install once — fatal only if the retry fails too. Post-install asserts: `/usr/share/zsh-syntax-highlighting/zsh-syntax-highlighting.zsh` and `/usr/share/zsh-autosuggestions/zsh-autosuggestions.zsh` required only if their package installed; `/etc/zsh_command_not_found` presence reported, never fatal.
- [ ] System defaults: idempotent `/etc/shells` entries (`/bin/zsh`, `/usr/bin/zsh`, `grep -qxF` guard); `/etc/zsh/zprofile` gets `emulate sh -c '. /etc/profile'` appended only if absent; deploy embedded templates to `/etc/skel/.zshrc`, `/etc/skel/.zprofile` (0644 root:root via `install`); `SHELL=/bin/zsh` in `/etc/default/useradd` (file absent ⇒ create it with the single line); `DSHELL=/bin/zsh` in `/etc/adduser.conf` (uncomment or replace; file absent ⇒ create it with the single line) — consistent with the absence-deletion restore contract.
- [ ] Per-user backup (before that user's deploy): `~/.zsh-backup-<UTC>` with user ownership, baseline dir + `-latest` symlink, snapshot `.bashrc`, `.bash_aliases`, `.profile`, pre-existing `.zshrc`/`.zprofile`/`.zshenv`, generated `restore-user.sh` including `chsh -s <prev_shell> <user>`. Backup-creation failure for a user ⇒ skip that user with WARN and continue. Same absence contract as the system backup: a path recorded as pre-run-absent is **deleted** by `restore-user.sh` (full pre-run state). Symlink snapshot semantics: for a symlinked path the snapshot stores separately the fact that it was a link and the bytes of its target; `restore-user.sh` writes target bytes through the existing link and never replaces an existing symlink with a regular file.
- [ ] Harvest & migration: diff `~/.bashrc` against skel template (root: also `/usr/share/base-files/dot.bashrc`) + `~/.bash_aliases` + portable lines from `~/.bash_profile` when present (same classifier; no double-sourcing risk since zsh never reads it); allowlist portable lines (export/PATH/alias/umask/non-startup source/depth-0 conditionals/zsh-safe `set -o` options); deny/warn list (PS1, PROMPT_COMMAND, SHELL, `export -f/-n`, bash-only constructs); **source targets resolving to startup files — `.profile`, `.bash_profile`, `.bash_login`, `.bashrc`, `.zprofile`, `.zshrc`, `.zshenv`, `/etc/profile` — are never harvested** (a classic `.bash_profile` stub sourcing `.profile` must not enter the marker block: it would double-source `.profile` alongside the embedded `.zprofile` → `.profile` chain); at deploy, each migrated `source`/`. <file>` line is wrapped in an existence guard (`[ -f <file> ] && . <file>`) so a missing target cannot error on every shell start; **`~/.profile` is deliberately NOT harvested** — it keeps working via the embedded `.zprofile` → `.profile` chain under `emulate sh -c` (documented contract above), so harvesting it would double-source it; append harvested lines inside `# >>> kali-zsh-setup: migrated user config >>>` marker block; skip block if nothing harvested; never duplicate markers on re-run.
- [ ] Deploy per-user profiles: `.zshrc` = embedded template + marker block, `.zprofile` = embedded template verbatim; per-user deploy is atomic: stage both files first, then move both into place — for regular-file targets; for a resolvable in-scope symlink, write into the resolved target via its explicit realpath path — GNU `install` must NOT be pointed at the link path (empirically it replaces the link with a regular file); a post-deploy assert `[ -L <link> ]` guards link integrity; a deploy failure invokes that user's `restore-user.sh` (full dotfile rollback) before the skip+WARN; `install -m 0644 -o <user> -g <group>`; write-through to `realpath` for resolvable symlinks (unresolvable or foreign-target ones were excluded in preflight). Deploy failure for a user ⇒ skip that user with WARN and continue.
- [ ] Pre-switch validation gate per user: isolated login zsh under the user's identity locally (`runuser -u <user> -- env HOME=<home> TERM=xterm-256color timeout --kill-after=5s 15s zsh -l -i -c 'autoload -Uz compinit && compinit -u && bindkey -e && exit 0'`; add `[[ -n $ZSH_HIGHLIGHT_VERSION ]]` only when the plugin is installed). rc 124 or 137 ⇒ VALIDATION_TIMEOUT (GNU `timeout` kill-after escalation empirically yields 137; ambiguity with OOM-kill is resolved by the probe re-run). Failure attribution, in priority order: first classify each individual failure — a failure local to the user (their pre-existing `~/.zshenv`/`~/.profile` or the deployed marker block misbehaving) ⇒ that user's `restore-user.sh` runs first (full dotfile rollback — deploy already happened), then the user is skipped (no `chsh`) with WARN and the run continues; systemic global abort applies only to environment/template-level failures (template hash mismatch, broken environment) or when every validated user failed AND none of the failures is attributable to a user-local cause; on global abort no login shell is touched. Attribution mechanism (discriminator): on a gate failure, re-run the identical gate once with a clean temporary HOME **pre-seeded with only the embedded template** (no harvested marker block, no user dotfiles) — it passes ⇒ the cause is user-local (the user's own `~/.zshenv`/`~/.profile`/marker block); it fails again ⇒ the cause is systemic (template, installed plugins, `/etc/zsh/*`). A bare empty HOME must NOT be used: zsh would not read `~/.zshrc` at all, so template/plugin failures would falsely classify as user-local. In a mixed set (some failures user-local, some probe-failing), each probe-failing user is skipped (no `chsh`) with WARN, the run continues, and the exit code follows the general warning policy. Gate side effects: `compinit -u` may create/update `~/.zcompdump` — declared a run artifact: excluded from the drift assertion, and `restore-user.sh` deletes it when it did not exist pre-run.

A failed non-root `chsh` ⇒ WARN and continue with the remaining users (each user's `restore-user.sh` already contains the `chsh` rollback). Only users validated above are switched; preflight-skipped users (missing HOME, broken/foreign symlink, non-`/etc/passwd`, ZDOTDIR), gate-skipped users (user-local validation failure), and backup-/deploy-failed users are never switched.

## Deferred empirical tests / blind-spot risks

- `[⏳ ACK-1]` command-not-found database on Debian 13: `/etc/zsh_command_not_found` needs a populated cache; if the package ships without it, the hook may error. Empirical check in smoke stage; never fatal.
- `[⏳ ACK-2]` Harvest classifier coverage on varied bash syntax: validated via the synthetic fixture test, not on live dotfiles.
- `[⏳ ACK-3]` Root dotfiles origin: `root`'s `.bashrc` may come from `/usr/share/base-files/dot.bashrc` rather than `/etc/skel/.bashrc`; preflight compares against both to avoid false-positive harvest.
- `[⏳ ACK-4]` `runuser`/`su` scripted login zsh (`zsh -l -i`, no pty, forced TERM) may differ from a real tty login. Mitigated by explicit env + timeout in the validation gate; residual divergence verified in smoke stage.

## Accepted scoped-down rationales

- System-wide scope (all interactive profiles + `/etc/skel` + default-shell configs) kept from the previously agreed requirement; not reduced to current-user-only.
- Single-file embedding chosen over script + `files/` bundle (see [`egm_lite_alternatives.md`](egm_lite_alternatives.md) Option A); runtime download rejected as non-autonomous.
- `--force-unlock` dropped: `flock` eliminates the stale-lock class it existed for.
- Root user inclusion kept (requirement: replace shell on all profiles).
- Line-based harvest with depth rule kept from previously approved reviews over embedding a heavy full shell parser.
- Users with unusable HOME, broken dotfile symlinks, or non-`/etc/passwd` (LDAP/SSSD) accounts are skipped with WARN/report instead of aborting the whole run (round-1 finding 3/4 policy).
- Validation-gate failures are attributed per-user (skip+WARN, no `chsh`) vs systemic (global abort) instead of abort-always, matching the skip-and-continue policy (round-2 finding 3 policy).
- Mid-pipeline per-user failures (backup, deploy, non-root `chsh`) skip the user with WARN and continue; smoke failures are non-fatal WARNs (round-3 finding 3 policy).
- Symlink write-through restricted to targets owned by the user or located inside their home (round-3 finding 4 policy).
